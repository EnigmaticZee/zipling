How it works

Most archivers squeeze bytes.
Zipling reads the file first.

Seven ideas make Zipling's archives smaller and faster than a zip. Here is what each one does, what it is worth in real numbers, and where it is still behind. All of it measured, every archive checked byte for byte.

  1. 1

    It re-encodes photos, without losing a bit.

    A JPEG is already compressed, so zipping it saves almost nothing. Zipling takes the numbers inside the JPEG apart and stores them with a coder built for exactly that kind of data. The photo comes back as the same file, bit for bit, and Zipling checks that before it keeps the smaller form.

    26%smaller than Finder's zip on a folder of photos
    19%smaller than 7-Zip's best setting
    30%saved on a typical JPEG

    The honest bit. This coder is for JPEGs. PNG screenshots and graphics have a coder of their own (next idea). HEIC photos from an iPhone are stored as they are.

  2. 2

    It unpacks what is already compressed.

    PDFs, PNGs, Office documents and disk images hide old, weak compression inside. Zipling undoes it exactly, compresses the raw data with a modern codec, and on the way out re-creates the original stream, byte for byte.

    PNGs go one step further at the Max setting. Once unpacked, Zipling's own pixel coder predicts each pixel from its neighbours and stores only the difference: 19% smaller than the strongest general-purpose compressor on the same pixels, and faster.

    56%smaller than Finder's zip on PDFs and screenshots
    42%smaller than 7-Zip's best on the same folder, at the default setting
    ¼smaller disk images at Max

    The honest bit. This only works where Zipling can reproduce the original compressor exactly; a stream it cannot reproduce is stored as it is, so nothing is ever changed. The pixel coder stays off at the default setting, which keeps extraction quick: unpacking alone already makes screenshots 56% smaller than a zip there.

  3. 3

    It keeps one copy of repeated data.

    The same photo in two folders, the same library in three apps, the same header in a thousand files: Zipling finds data that repeats anywhere in what you are compressing and stores it once.

    The honest bit. The gain depends entirely on your files. A folder with nothing repeated gains nothing here; a backup with old copies gains a lot.

  4. 4

    It lines up app code.

    A Mac app is mostly machine code for Apple silicon. Zipling rewrites the jumps inside it so that similar instructions look the same, which lets the compressor see the repeats.

    35%smaller than Finder's zip on eight Mac apps
    9%smaller than 7-Zip's best, in less than half the time

    The honest bit. Intel code is not filtered yet. Universal apps get the Apple silicon half treated and the Intel half compressed as it is.

  5. 5

    It uses every core, all the time.

    Files stream into independent blocks that every core of your Mac compresses at once, and extraction works the same way. Nothing waits for a single slow step.

    0.5 sto pack a 736 MB folder at Fast. Finder takes 24 s.
    9 sat the default setting, 34% smaller than Finder's zip
    5×faster to extract than Finder

    The honest bit. Max is slower than the default: 19 s instead of 9 on that folder, for an archive 10% smaller. Still faster than Finder, and you can let Zipling shrink an archive to Max later, while the Mac is idle.

  6. 6

    It carries its own repair data.

    Tick one box and a Zipling archive stores repair data inside itself, 3% of its size unless you choose more. If a disk fails or a download breaks, Zipling rebuilds the damaged parts exactly, even when the end of the file is missing or bytes have shifted. ZIP and 7z get a small recovery file beside them.

    3%of the archive repairs up to 3% of damage, anywhere in it
    1 to 50%your choice, for files that matter

    The honest bit. Damage beyond what the repair data covers is reported, not guessed: Zipling names the files that are lost.

  7. 7

    It checks everything, twice.

    Every block carries a keyed checksum and the index a BLAKE3 hash. Zipling verifies them while it writes the archive and again while it extracts, and every transform above is proved by rebuilding the original before the smaller form is kept.

    The honest bit. Zipling archives cannot be locked with a password yet; that is planned. For anything private today, choose ZIP or 7z, which Zipling encrypts with AES-256.

Where it is still behind

Not everything, not yet.

The same benchmarks that show the wins show these. They are measured on the same Mac, with every archive extracted and compared.

Data with nothing to read

On the standard Silesia corpus, generic data with no file types to exploit, the default setting is 16% bigger than 7-Zip's default (57.3 MB against 49.6 MB). Max is 4% smaller than 7-Zip's best, and eight times faster, but the default is built for real folders, not for this.

Source code at the default setting

On 89 Rust crates the default is 3% bigger than 7-Zip's default (9.5 MB against 9.2 MB), in a seventh of the time. Max matches the best of xz at 8.3 MB.

Intel Macs

Zipling runs on Apple silicon today. An Intel build is planned, and the code filter for Intel apps with it.

RAR

Zipling opens RAR archives, including locked ones, but does not create them. RAR is proprietary; convert one to a Zipling archive or a zip instead.

Ultra*

An experimental setting in the engine squeezes 0 to 3% more than Max for up to twice the time. It is not in the app and will not be until it earns its place.

Numbers move

Times vary about 10% between runs, and the default setting's archive size varies by up to 0.3% because blocks are cut by whichever core gets there first. The files inside never vary.
